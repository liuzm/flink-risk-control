## 1. 设计目标

本技术方案将当前单实例 Flink 风控 Demo 演进为可运营的多租户 SaaS。设计必须同时满足以下结果：

1. 平台运营端与租户工作台可以安全地管理各自资源。
2. 同步在线决策和异步流式检测共享同一套规则语义与版本体系。
3. 租户、应用和环境上下文贯穿请求、事件、规则、状态、存储、缓存和输出。
4. 控制面短时故障不影响已发布配置继续运行。
5. 所有生产变更可校验、可审批、可审计、可回滚。
6. 用量、配额、服务质量和账单可以按租户对账。
7. 系统可以从共享资源平滑升级到企业专属资源。

## 2. 当前代码基线

| 模块 | 当前职责 | 已具备能力 | SaaS 关键缺口 |
|---|---|---|---|
| frontend | Ant Design Pro 管理端与产品官网 | 概览、规则、风险、看板、官网 | 无登录、租户上下文、权限菜单和完整工作台 |
| flink-risk-web | Spring Boot 管理 API | 规则 CRUD、风险查询、基础统计 | Controller 直连 CRUD，无领域层、认证、审计和租户过滤 |
| flink-risk-common | 事件、规则和结果公共模型 | 三类事件、Aviator、RiskResult | 模型无 tenant/app/env/version/decisionId |
| flink-risk-job | Flink CEP 作业 | 三类 Kafka Source、六类 CEP、规则广播、三路 Sink | 只按 userId 分区、全局规则快照、MySQL 轮询、无幂等 |
| MySQL | 规则与风险结果 | rule_config、risk_result | 无控制面实体、版本、审计、租户索引 |
| Redis | 风险结果缓存 | 一小时 TTL | Key 无租户作用域，无在线特征与配额模型 |
| Kafka | 事件输入和风险输出 | 三类输入 Topic、risk-results | 无受信任事件信封、ACL、坏数据和计量 Topic |
| Docker Compose | 本地一体化部署 | MySQL、Redis、Kafka、Flink、Web | 单节点、明文凭证、无高可用与环境隔离 |

## 3. 目标范围

### 3.1 V1.0 技术范围

- 统一身份、租户、成员、角色、应用和环境。
- 共享逻辑隔离，并预留增强/专属资源路由。
- 控制面模块化后端和租户安全数据访问层。
- 同步 Decision API 与在线规则运行时。
- 多租户 Flink CEP、配置快照与可靠输出。
- 规则测试、审批、发布、ACK 和回滚。
- 套餐权益、实时配额、不可变用量账本和基础账单。
- 风险记录、审核反馈、通知、工单和审计底座。
- 指标、日志、追踪、告警、备份和迁移方案。

### 3.2 V1.0 非目标

- 自研机器学习训练平台和复杂特征工程平台。
- 跨机构数据联盟和外部征信市场。
- 自动支付、自动开票、多币种和渠道分账。
- 跨地域双活；V1.0 先实现单 Region 多可用区。
- 为每个小租户独立部署全套基础设施。
- 在第一阶段拆成大量独立微服务。

## 4. 设计基线与容量假设

以下数值用于第一版架构设计和压测，不是最终商务承诺，业务数据明确后必须重新容量评审。

| 维度 | V1.0 设计基线 | 扩展目标 |
|---|---:|---:|
| 已开通租户 | 100 | 1,000 |
| 同时活跃生产租户 | 20 | 200 |
| 平台总峰值 | 10,000 EPS | 100,000 EPS / 资源池 |
| 单租户默认峰值 | 1,000 EPS | 企业专属按合同 |
| 同步决策并发 | 1,000 | 水平扩展 |
| 单事件大小 | P95 ≤ 8 KB，最大 32 KB | 超限拒绝 |
| 单作用域生效规则 | 300 | 2,000 |
| 在线决策目标 | P95 ≤ 200 ms | P99 单独评审 |
| 流式结果目标 | 模式成立后 P95 ≤ 10 s | 按窗口语义 |
| 风险明细在线保留 | 180 天 | 套餐/合规可覆盖 |
| 审计保留 | 至少 1 年 | 合规可延长 |

## 5. 质量属性优先级

| 优先级 | 质量属性 | 设计要求 |
|---:|---|---|
| 1 | 租户隔离 | 跨租户泄露为零；不存在默认租户回退 |
| 2 | 决策正确性 | 输入、配置和特征版本相同时结果可复现 |
| 3 | 可用性 | 控制面故障不打断最后稳定配置的数据面 |
| 4 | 低延迟 | 同步主链路只使用内存快照和有预算的依赖 |
| 5 | 可审计 | 身份、配置、发布、数据访问和支持操作全量留痕 |
| 6 | 可扩展 | 无状态服务水平扩展，租户可迁移到专属资源 |
| 7 | 可维护 | 领域边界明确，禁止跨模块直接修改权威数据 |

## 6. 技术约束

- 继续使用现有 MySQL、Redis、Kafka、Flink、Spring Boot 和 Ant Design Pro 技术栈，降低迁移成本；外部集成采用 OpenAPI 网关，内部服务通信采用 Dubbo 统一契约。
- 控制面目标运行时统一到 Java 17；Flink 运行时的 JDK 升级先做兼容性 PoC。
- V1.0 控制面采用模块化单体，在线决策和 Flink 数据面独立部署。
- 所有外部契约以 OpenAPI、JSON Schema 或消息 Schema 作为权威来源。
- 所有密钥由 Secret Manager/KMS 管理，不进入代码、镜像和配置仓库。
- 生产环境禁止自动建 Topic、自动改表和应用启动时执行不可逆迁移。

## 8. 开放决策

1. 首发平均/峰值 EPS 和热点主体分布。
2. Flink 目标运行时 JDK 与现有 Savepoint 兼容策略。
3. 身份提供方采用自建、托管还是企业现有 IdP。
4. 企业专属资源从哪个套餐和隔离等级开始提供。
5. V1.0 是否要求多可用区数据库自动切换。
6. 审计和业务数据的法定保留、驻留及删除要求。
