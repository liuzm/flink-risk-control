# RiskFlow 技术方案设计

本目录用于承接 [产品 PRD](../product-prd/README.md) 对应的系统架构、关键技术决策、接口、数据、安全、部署和验收方案。

> 当前版本：v0.1 评审稿  
> 设计基线：控制面模块化单体，在线决策服务与 Flink 数据面独立，多租户通过可信上下文与资源路由贯穿全部技术层。

## 设计原则

1. 产品需求与技术实现一一映射。
2. 控制面与实时数据面解耦。
3. 租户上下文贯穿身份、接口、存储、缓存、消息和计算状态。
4. 所有生产配置版本化、可审计、可回滚。
5. 先定义契约、状态与故障边界，再确定具体组件。
6. 性能、安全和可观测性作为主流程设计，不作为上线前补丁。

## 推荐设计顺序

1. 先完成 00–03，锁定边界、租户模型和安全上下文。
2. 完成 04–07，定义核心数据、两类决策链路和隔离基线。
3. 完成 14，确认平台化边界、租户生命周期与运维模型。
4. 完成 08–09，定义发布一致性与计量/计费联动。
5. 完成 10–11，补齐安全、治理和运行保障。
6. 完成 12–13，形成可执行的迁移、交付和验收计划。

## 已确定的技术基线

- V1 控制面采用模块化单体，避免过早拆分大量微服务。
- 在线同步决策与 Flink 流式判定独立部署，共享规则快照和事实模型。
- 租户上下文只能由可信认证边界生成，并贯穿 SQL、Redis、Kafka、Flink 与对象存储。
- 标准租户共享 Schema；增强/专属租户通过 ResourceRoute 迁移物理资源。
- 配置采用不可变快照和 PREPARE/ACTIVATE 协议，不再以 MySQL 轮询作为目标方案。
- 判定事实、审计和用量账本采用追加写；跨组件一致性使用 Outbox、回执和幂等补偿。

## 单章完成标准

每章至少包含：

- 目标与非目标
- 产品需求映射
- 当前实现与差距
- 目标架构或处理流程
- 核心接口与数据
- 异常、降级和一致性策略
- 安全与多租户约束
- 性能容量假设
- 方案取舍与 ADR
- 测试及验收标准
- 风险和待决策项
