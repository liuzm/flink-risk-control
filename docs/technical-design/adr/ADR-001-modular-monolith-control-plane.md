# ADR-001：控制面采用模块化单体

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[目标系统架构](../01-target-architecture.md)

## 背景

V1 要同时建设租户、权限、应用、策略、发布、运营、计量和审计。当前后端是单一 Spring Boot 应用，团队与业务规模尚不足以承担大量微服务的部署、事务和运维成本，但领域边界必须从一开始清晰。

## 决策

控制面采用一个 Spring Boot 部署单元、多个强边界业务模块：

- 每个模块拥有 API、应用服务、领域对象和数据访问层。
- 模块只能写自己的表；跨模块通过公开接口或领域事件。
- 禁止通用 service/mapper 绕过模块边界。
- 在线决策、Flink 数据面仍作为独立部署单元。
- 使用架构测试检查包依赖和越界访问。

## 备选方案

1. 完整微服务：隔离更强，但会显著增加服务治理、分布式一致性与部署成本。
2. 传统分层单体：实施快，但领域耦合会迅速扩大，后续难拆。
3. Serverless 函数：适合事件任务，不适合复杂一致性控制面作为主形态。

## 影响

收益是事务简单、交付速度高、局部重构成本低；代价是需要严格模块纪律，单个部署发布影响面更大。达到独立扩容、合规隔离或团队所有权阈值时，可基于既有模块边界拆服务。

## 验证

- CI 架构测试无跨模块非法依赖。
- 数据写入方唯一。
- 单模块可通过契约测试独立验证。
- 在线决策压力不影响控制面线程池和发布。
