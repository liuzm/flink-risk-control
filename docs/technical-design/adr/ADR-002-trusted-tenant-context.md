# ADR-002：租户上下文只能由可信边界生成

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[多租户架构](../02-multi-tenant-architecture.md)、[身份与权限](../03-identity-and-access.md)

## 背景

客户端可伪造 Header、路径和正文中的 tenantId。如果业务服务直接信任这些字段，任何遗漏都可能形成跨租户访问。租户作用域还必须贯穿缓存、消息和 Flink 状态。

## 决策

- 网关从已验证用户/服务凭证映射出 TenantContext。
- 外部传入的 tenantId 仅作为资源参数参与归属校验，不作为权限事实。
- 内部调用通过签名 token 或 mTLS 工作负载身份传播上下文。
- 数据查询、Redis Key、Kafka Envelope、Flink Key 和对象路径都包含完整 scope。
- 平台支持访问使用独立、短期、带授权单的 SupportSessionContext。
- 缺失或冲突上下文默认拒绝。

## 备选方案

1. 每个接口接收 tenantId：实现简单，但极易因遗漏产生越权。
2. 每租户独立域名推断：可辅助路由，不能代替凭证授权。
3. 数据库连接级租户：防护强，但不能覆盖消息、缓存和计算状态。

## 影响

所有公共库和数据访问层必须接受上下文，测试成本增加；但隔离策略一致且可自动验证。异步事件必须保存 scope，不能依赖线程本地变量。

## 验证

使用 A/B 租户相同资源编码、subjectId、eventId 覆盖 API、SQL、Redis、Kafka、Flink、导出和恢复测试，任何串租均阻断发布。
