# ADR-003：运行时配置采用不可变快照与 PREPARE/ACTIVATE

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[配置与发布](../08-configuration-and-release.md)

## 背景

当前 Flink 每 30 秒从 MySQL 轮询全局规则列表，无法证明某次判定使用了哪个完整配置，也无法保证多实例同时生效或安全回滚。

## 决策

- 发布服务把已审批修订编译成不可变 RuntimeSnapshot。
- 快照带 scope、version、schema、checksum、最低运行时版本和完整依赖。
- 通过 Kafka 发送 PREPARE，运行实例下载、校验、编译和预热并回执。
- 达到就绪条件后发送 ACTIVATE，实例用原子引用切换。
- 控制面只有收到激活 quorum 才显示 ACTIVE。
- 回滚通过重新激活上一稳定快照完成。
- 命令使用 Outbox，实例按 scope + version + command 幂等。

## 备选方案

1. 运行时轮询数据库：简单，但延迟、扩展、审计和一致性均不足。
2. 直接推送规则增量：流量小，但容易出现缺项和中间状态。
3. 分布式事务：无法合理覆盖 Kafka、Flink 和内存状态，复杂且脆弱。

## 影响

需要快照存储、编译器、配置回执和状态机；换来可追溯、可预热、原子切换与可靠回滚。快照 schema 和 runtime 需要兼容矩阵。

## 验证

重复/乱序命令、部分实例失败、扩缩容、实例重启、checksum 篡改和较低版本回滚都必须通过集成测试。
