# ADR-004：标准租户共享 Schema，企业租户通过资源路由增强隔离

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[多租户架构](../02-multi-tenant-architecture.md)、[领域与数据](../04-domain-and-data.md)

## 背景

V1 需要可控成本地支持大量中小租户，同时为大客户、合规和噪声邻居提供专属资源。如果一开始每租户独立全栈，运维与升级成本过高；只做共享资源又无法满足企业需求。

## 决策

- 标准租户使用共享 MySQL schema，所有表和唯一索引包含 tenant_id。
- Redis、Kafka、Flink state、对象存储同步采用作用域命名和 ACL。
- ResourceRoute 记录租户各资源域实际落点。
- 隔离等级为 SHARED、ENHANCED、DEDICATED。
- 外部 API 和领域模型不感知物理路由。
- 租户可通过双写、核对、切路由迁移到专属库/topic/job/cache。

## 备选方案

1. 每租户数据库：隔离好，初始化、连接和迁移成本高。
2. 只共享不支持迁移：简单，但无法满足大型客户和风险隔离。
3. 按租户独立部署整个平台：适合极少数私有化，不适合作为 SaaS 默认。

## 影响

数据访问必须统一经过路由层，迁移与核对工具成为基础能力。共享层需强制隔离测试和租户公平性保护。

## 验证

完成默认租户从共享资源迁移到专属资源再回切的演练，期间 API 不变、事实不丢、用量不重。
