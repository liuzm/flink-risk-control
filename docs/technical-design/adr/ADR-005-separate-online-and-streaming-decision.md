# ADR-005：在线决策与流式决策独立运行

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[在线决策](../06-online-decision-engine.md)、[Flink 运行时](../07-flink-streaming-runtime.md)

## 背景

同步请求要求可控的百毫秒级延迟和明确超时；Flink 擅长事件时间、窗口、CEP 与状态恢复。把同步 API 强行放进 Flink 会增加请求关联、超时和背压复杂度；只用同步服务又无法高效支持跨事件状态。

## 决策

- Decision Service 处理同步单次判定和低延迟在线特征。
- Flink 处理异步事件、窗口聚合、CEP、迟到与重放。
- 两者共享 RuntimeSnapshot、事件契约、原因码和判定事实模型。
- 特征可由 Flink 预聚合写入在线特征库供同步服务读取。
- 两条链路的结果都进入统一 decision fact topic。
- 明确 processingMode=SYNC/STREAM/REPLAY，避免把不同时间语义混为一谈。

## 备选方案

1. 全部基于 Flink：状态能力强，但同步 RPC 语义和尾延迟复杂。
2. 全部基于普通服务：同步简单，但窗口、CEP 和恢复能力重复建设。
3. 两套完全独立规则系统：短期快，长期结果漂移且难审计。

## 影响

需要维护两个运行时适配器和兼容测试，但共享编译 IR 可降低语义漂移。涉及强实时窗口的规则需明确由哪条链路作为权威。

## 验证

同一无状态规则在两类运行时输出一致；有状态规则通过固定事件时间的黄金数据集验证。两条链路故障互不拖垮。
