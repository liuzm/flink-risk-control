# ADR-006：计量采用不可变用量账本

- 状态：已接受（V1 设计基线）
- 日期：2026-08-16
- 关联：[计量与计费](../09-metering-and-billing.md)

## 背景

Redis 计数适合实时限额，但不能作为可审计账单事实；Kafka 至少一次交付和内部重试还可能导致重复计量。直接修改月累计无法说明账单如何得到。

## 决策

- 每次可计量行为产生唯一 usageEventId。
- UsageLedger 只追加，重复事件由唯一键去重。
- 更正通过 REVERSAL/ADJUSTMENT 流水，不更新原记录。
- Redis 只执行实时配额，通过账本定期校准。
- 分钟/小时/日/账期聚合保留水位、修订版本和计算版本。
- 账单冻结权益快照与价格版本，已出账只通过贷项/补项调整。

## 备选方案

1. 只用 Redis 计数：性能高，但丢失、恢复和审计不足。
2. 直接维护月累计表：简单，但重复/迟到/更正难追溯。
3. 依赖外部计费平台作为唯一事实：减少自研，但仍需可信原始计量与对账。

## 影响

存储与聚合复杂度上升，但能支持重复、迟到、重算、争议处理和审计。V1 可先生成账单草稿，再接外部支付/发票。

## 验证

注入重复、乱序、迟到和消费重放，最终账期数量唯一正确；任意账单行可追溯到用量、价格与权益版本。
