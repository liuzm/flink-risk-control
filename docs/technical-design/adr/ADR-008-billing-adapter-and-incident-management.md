# ADR-008：计费外部适配与故障事件管理边界分离

- 状态：已接受（V1 设计基线）
- 日期：2026-08-17

## 背景

V1.0 目标强调先闭环风险决策与可计费能力。若计费直接耦合决策、配置和故障流程，可能产生以下风险：

- 决策链路偶发抖动导致账单异常；
- 支付失败或退款策略改变影响决策时效；
- 账务争议处理与应急发布路径混淆，导致复盘失焦；
- 跨租户告警不能与故障工单一致追踪。

产品对账期望是：同一月度口径内，`用量 -> 帐本 -> 账单 -> 对账` 可溯源，但不强制 V1.0 实现在线支付与自动开票。

## 决策

1. 计费系统采用“核心计量事实内聚 + 外部收款适配器”双层结构：
   - 核心平台只负责 `usage_ledger`、权益快照、账期聚合与账单草稿生成；
   - 收款/发票/税务走独立 Billing Adapter（可选插件化），通过 Outbox 事件触发对账建议，不参与在线决策关键路径。
2. `bill` 的最终状态机限制为：
   - `DRAFT -> REVIEWED -> ISSUED -> PAID_OR_OFF_CHAIN_SETTLED -> CLOSED`；
   - 外部支付成功由外部适配器回写“确认/失败/冲正”事件，不在同步决策 API 返回中出现阻塞。
3. 外部适配器事件要求幂等和逆向补偿：
   - 发起动作与回执均带 `billingEventId`；
   - 失败重试不得重复计费。
4. 引入统一 `incident` 作为故障主线闭环对象：
   - `alert` 聚合为 `incident`，并承载 `owner`、SLA、影响范围、根因与修复动作；
   - 支持会话与工单仅引用 `incident` 进行全局追踪；
   - 支持会话结束后必须回写处理结果到 `incident`。
5. 计费和故障管理的服务接口在版本化 API 中单独分组，支持不同变更节奏（计费变更可缓慢发布，决策链路严格限变）。

## 备选方案

1. 将支付和账单全量内置到决策控制面：
   - 优点：功能单点完整。
   - 风险：上游抖动时账单不可用概率上升，扩展财务系统成本高。
2. 不做 incident 概念，告警与工单直接扁平化处理：
   - 优点：模型最小。
   - 风险：无法稳定复用故障时间线、SLA 归责与平台治理。
3. 把计费完全外包给第三方平台：
   - 优点：上线快。
   - 风险：`usage_ledger` 与第三方账单对账仍需自研核对与反争议流程。

## 影响

- 计费链路与实时风控链路解耦，减少因收款异常导致的判定退化。
- 账务争议有明确事件链路，便于补退和审计。
- incident 统一了告警升级、工单联动、支持会话和发布影响范围回溯，SLA 考核更可追责。
- 需要补充的交付项：Billing Adapter 接口规格、账务事件回执 schema、incident 生命周期与工单状态映射。

## 验证

- 在无支付回调场景下，在线决策与配置发布仍可独立运行，账单状态可落在 DRAFT/REVIEWED 阶段。
- 发送/接收双向计费事件时，重复请求不产生重复账单行。
- 一个 incident 在告警聚合、支持会话、工单关闭与公告发布间可形成完整时间线。
